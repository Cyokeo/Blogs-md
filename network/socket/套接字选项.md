# SO_NOSIGPIPE
用于控制当向已关闭的连接写入数据时是否生成 `SIGPIPE` 信号。

## 1. **问题背景：SIGPIPE 信号**

### 1.1 **什么是 SIGPIPE？**
```cpp
// 典型场景：
// 1. 进程A向进程B的套接字写入数据
// 2. 进程B关闭了连接（正常关闭或崩溃）
// 3. 进程A继续写入 → 触发 SIGPIPE 信号
// 4. 默认行为：终止进程！
```
### 1.2 **为什么会有 SIGPIPE？**
- **历史原因**：在早期的 Unix 系统中，管道（pipe）通信很常见
- **错误处理**：防止进程向不存在的读取端写入数据
- **快速失败**：避免无意义的写入操作消耗资源

## 2. **SO_NOSIGPIPE 的作用**

### 2.1 **基本功能**
```cpp
// 设置 SO_NOSIGPIPE 后：
// 1. 写入已关闭的连接不会产生 SIGPIPE 信号
// 2. 写入操作返回错误（通常 EPIPE）
// 3. 进程不会被意外终止
```

### 3.2 **发送数据时的变化**
```cpp
// 没有 SO_NOSIGPIPE
ssize_t ret = send(sock, buffer, size, 0);
// 如果连接已关闭：进程收到 SIGPIPE 信号，默认终止

// 有 SO_NOSIGPIPE
int val = 1;
setsockopt(sock, SOL_SOCKET, SO_NOSIGPIPE, &val, sizeof(val));
ssize_t ret = send(sock, buffer, size, 0);
// 如果连接已关闭：返回 -1，errno = EPIPE，进程继续运行
```

# SO_LINGER
用于控制套接字关闭时的行为，特别是如何处理尚未发送的数据

## 1. **基本概念**
### 1.1 **默认关闭行为**
```cpp
// 默认情况下，close() 或 shutdown() 立即返回
// 但操作系统会在后台尝试发送剩余数据
close(sockfd);  // 立即返回，数据可能还在发送
```
### 1.2 **问题场景**
```cpp
// 1. 发送缓冲区还有数据没发完
// 2. 调用 close() 关闭套接字
// 3. 对端可能收不到最后的数据
// 4. 或者收到不完整的数据
```
## 2. **SO_LINGER 的结构**
### 2.1 **linger 结构体**
```cpp
#include <sys/socket.h>

struct linger {
    int l_onoff;   // 0=关闭, 非0=启用
    int l_linger;  // 等待时间（秒）
};
```
### 2.2 **可能的值以及close的行为**
```cpp
struct linger lin;

// 情况1：禁用 lingering（默认）
lin.l_onoff = 0;
lin.l_linger = 0;  // 忽略
// 行为：立即关闭，尝试发送剩余数据（非阻塞）

// 情况2：启用 lingering，l_linger = 0
lin.l_onoff = 1;
lin.l_linger = 0;
// 行为：立即关闭，丢弃未发送数据，发送 RST

// 情况3：启用 lingering，l_linger > 0
lin.l_onoff = 1;
lin.l_linger = 5;  // 等待5秒
// 行为：阻塞等待数据发送完成，超时则丢弃
```
## 3. **不同设置的行为**
### 3.1 **禁用 SO_LINGER（默认）**
```cpp
// 默认行为
struct linger lin = {0, 0};
setsockopt(sock, SOL_SOCKET, SO_LINGER, &lin, sizeof(lin));

// close() 行为：
// 1. 立即返回
// 2. 内核尝试在后台发送剩余数据
// 3. 如果数据成功发送 → 正常关闭
// 4. 如果失败 → 发送 RST 重置连接
// 5. close() 可能成功，但对端可能收不到数据
```
### 3.2 **启用 SO_LINGER，l_linger = 0**
```cpp
// 立即关闭，不等待
struct linger lin = {1, 0};
setsockopt(sock, SOL_SOCKET, SO_LINGER, &lin, sizeof(lin));

// close() 行为：
// 1. 立即丢弃发送缓冲区数据
// 2. 发送 TCP RST 重置连接（不是正常关闭）
// 3. 对端收到 ECONNRESET 错误
// 4. 快速释放资源，但可能丢失数据
```
### 3.3 **启用 SO_LINGER，l_linger > 0**
```cpp
// 阻塞等待数据发送
struct linger lin = {1, 10};  // 等待10秒
setsockopt(sock, SOL_SOCKET, SO_LINGER, &lin, sizeof(lin));

// close() 行为：
// 1. 如果发送缓冲区为空 → 立即返回
// 2. 如果还有数据 → 阻塞等待发送完成
// 3. 超时（10秒）后仍有数据 → 丢弃并返回 EWOULDBLOCK
// 4. 确保对端收到数据（在超时内）
```
## 7. **注意事项和陷阱**

### 7.1 **close() 可能阻塞**
```cpp
// 设置了 SO_LINGER 且 l_linger > 0 时
struct linger lin = {1, 30};  // 等待30秒
setsockopt(sock, SOL_SINGER, SO_LINGER, &lin, sizeof(lin));

// close() 可能阻塞30秒！
close(sock);  // 危险：可能长时间阻塞

// 解决方案：使用非阻塞套接字或设置合理的超时
```
### 7.2 **与 shutdown() 的区别** !!!!!
```cpp
// shutdown() 和 SO_LINGER 的区别：
// shutdown(SHUT_WR): 停止发送，但可以继续接收
// close() with SO_LINGER: 完全关闭连接

// 推荐组合使用：
void graceful_close(int sock) {
    // 1. 停止发送
    shutdown(sock, SHUT_WR);  // 发生FIN终止连接，对端收到并处理后，不会再请求重传
    
    // 2. 读取对端可能发送的剩余数据
    char buffer[1024];
    while (recv(sock, buffer, sizeof(buffer), 0) > 0) {
        // 丢弃或处理
    }
    
    // 3. 完全关闭
    close(sock);
}
```
### 7.3 **TIME_WAIT 状态**
```cpp
// SO_LINGER 影响 TIME_WAIT 状态：
// - 正常关闭：主动关闭方进入 TIME_WAIT（2MSL）
// - SO_LINGER=0：可能跳过 TIME_WAIT，发送 RST

// TIME_WAIT 的作用：
// 1. 确保最后一个 ACK 到达
// 2. 防止旧连接的包干扰新连接
// 3. 通常持续 60 秒（Linux）

// 使用 SO_LINGER=0 可以避免 TIME_WAIT
// 但可能影响协议可靠性
```
## 4. **TCP 状态机视角**
### 4.1 **正常关闭流程**
```cpp
// 应用层：发送所有数据
// 应用层：shutdown(SHUT_WR) → 发送 FIN
// TCP层：进入 FIN_WAIT_1
// 对端：收到 FIN，发送 ACK
// TCP层：进入 FIN_WAIT_2
// 对端：发送自己的 FIN
// TCP层：发送 ACK，进入 TIME_WAIT %%
```
### 4.2 **shutdown 过早的问题**
```text
应用层：发送数据包#10
应用层：立即 shutdown(SHUT_WR) → 发送 FIN
TCP层：数据包#10 还在传输中/未确认
对端：收到 FIN，但还没收到数据包#10
对端：可以 ACK FIN，但数据包#10 丢失了
对端：请求重传#10，但发送方已不能重传
结果：数据丢失！
```

## 5. **Asio 中的正确处理**
### 5.1 **异步确保发送完成**
```cpp
void async_graceful_close(asio::ip::tcp::socket& socket) {
    // 1. 异步发送所有数据
    asio::async_write(socket, asio::buffer(final_data),
        [&socket](asio::error_code ec, size_t /*length*/) {
            if (!ec) {
                // 2. 所有数据发送完成后 shutdown
                socket.shutdown(asio::ip::tcp::socket::shutdown_send);
                
                // 3. 可选：读取对端剩余数据
                asio::async_read(socket, asio::dynamic_buffer(receive_buffer),
                    [&socket](asio::error_code ec, size_t length) {
                        // 4. 完全关闭
                        socket.close();
                    });
            } else {
                // 错误处理
                socket.close();
            }
        });
}
```
### 5.2 **使用 completion token**
```cpp
// Asio 方式：确保异步操作完成
template <typename CompletionToken>
auto async_send_and_close(asio::ip::tcp::socket& socket,
                          const std::string& data,
                          CompletionToken&& token) {
    return asio::async_write(socket, asio::buffer(data),
        [&socket](asio::error_code ec, size_t,
                  auto&& completion_handler) {
            if (!ec) {
                socket.shutdown(asio::ip::tcp::socket::shutdown_send);
            }
            socket.close();
            std::move(completion_handler)(ec);
        }, std::forward<CompletionToken>(token));
}
```
## 7. **总结**
**关键要点**：
1. **`shutdown(SHUT_WR)` 后不能重传**：写方向完全关闭，TCP 不能发送任何数据包（包括重传）
2. **正确顺序**：
    - 确保所有数据**已发送且被确认**
    - 然后调用 `shutdown(SHUT_WR)`
    - 然后读取对端可能的数据
    - 最后 `close()`
3. **解决方案**
    - **使用 `SO_LINGER`**：让 `close()` 等待数据发送完成
    - **应用层确认**：实现自己的可靠关闭协议
    - **异步等待**：使用 Asio 等框架确保异步操作完成
4. **最佳实践**
    - 重要数据：使用应用层确认
    - 一般数据：使用 `SO_LINGER` 合理超时
    - 高并发：异步非阻塞关闭

**记住**：网络编程中的优雅关闭需要仔细设计，不能简单地在发送数据后立即 `shutdown(SHUT_WR)`。
