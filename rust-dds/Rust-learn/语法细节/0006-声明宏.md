# Rust 宏的另一半：**声明宏（Macro Rules）**

Rust 的宏系统分为两大阵营：

1. **过程宏（Proc Macros）**：你之前学的 `#[derive(Serialize)]` 就是这类，在编译期运行，接收代码返回代码。
2. **声明宏（Declarative Macros）**：也叫 **`macro_rules!` 宏**，Rust 最古老、最常用的宏，核心是 **「模式匹配」**—— 像 `match` 语句一样匹配代码结构，然后生成新代码。

今天我们就彻底搞懂声明宏，结合你熟悉的 `vec!`、`println!` 等标准库宏，从原理到实践。

---

## 一、先看直观例子：你每天都在用的声明宏

你一定用过这些标准库宏，它们都是 `macro_rules!` 定义的声明宏：
```rust
// 1. vec!：创建 Vec
let v = vec![1, 2, 3];

// 2. println!：打印到控制台
println!("Hello, {}!", "world");

// 3. format!：生成字符串
let s = format!("The answer is {}", 42);

// 4. assert!：断言
assert!(1 + 1 == 2);
```

这些宏的核心特点是：

- **用 `!` 结尾**：这是宏的标志（区分于函数）；
- **基于模式匹配**：匹配你传入的代码结构，生成对应逻辑。

---

## 二、声明宏的核心：`macro_rules!` 语法

声明宏用 `macro_rules!` 关键字定义，核心结构是：
```rust
macro_rules! 宏名 {
    // 模式 1 => 生成的代码 1
    (模式1) => { 代码1 };
    // 模式 2 => 生成的代码 2
    (模式2) => { 代码2 };
    // ... 更多模式
}
```

### 1. 最简单的声明宏：`hello!`

我们先写一个最简单的宏，打印 "Hello, World!"：
```rust
macro_rules! hello {
    // 模式：空括号（不接受任何参数）
    () => {
        // 生成的代码：调用 println!
        println!("Hello, World!");
    };
}

fn main() {
    hello!(); // 调用宏，输出：Hello, World!
}
```

---

### 2. 带参数的声明宏：`greet!`

我们让宏接受一个参数（名字），打印 "Hello, 名字！"：
```rust
macro_rules! greet {
    // 模式：接受一个表达式（$name:expr）
    ($name:expr) => {
        println!("Hello, {}!", $name);
    };
}

fn main() {
    greet!("Alice"); // 输出：Hello, Alice!
    greet!("Bob");   // 输出：Hello, Bob!
}
```

#### 关键语法：`$name:expr`

声明宏的参数用 `$` 开头，格式是：
```txt
$变量名:类型标记
```

常见的类型标记（Fragment Specifiers）：

|标记|含义|例子|
|---|---|---|
|`expr`|表达式|`1 + 2`、`"hello"`|
|`ty`|类型|`i32`、`String`|
|`pat`|模式|`Some(x)`、`(a, b)`|
|`stmt`|语句|`let x = 1;`|
|`block`|代码块|`{ ... }`|
|`ident`|标识符|`x`、`my_function`|
|`tt`|Token Tree（任意 Token）|几乎任何代码片段|

---

### 3. 多模式匹配：`add!`

声明宏可以像 `match` 一样匹配多个模式，我们写一个 `add!` 宏，支持 1 个或 2 个参数：
```rust
macro_rules! add {
    // 模式 1：1 个参数，返回它自己
    ($x:expr) => { $x };
    // 模式 2：2 个参数，返回它们的和
    ($x:expr, $y:expr) => { $x + $y };
}

fn main() {
    assert_eq!(add!(5), 5);          // 匹配模式 1
    assert_eq!(add!(2, 3), 5);       // 匹配模式 2
}
```

---

### 4. 重复模式：`vec!` 的核心秘密

声明宏最强大的功能是**重复模式**，用 `$(...)*` 或 `$(...)+` 表示 “重复零次或多次” 或 “重复一次或多次”。

这就是 `vec!` 宏的核心原理！我们写一个简化版的 `my_vec!`：
```
macro_rules! my_vec {
    // 模式：接受零个或多个表达式，用逗号分隔
    ($($x:expr),*) => {
        {
            let mut temp_vec = Vec::new();
            // 重复：对每个 $x 执行 push
            $(
                temp_vec.push($x);
            )*
            temp_vec
        }
    };
}

fn main() {
    let v = my_vec![1, 2, 3, 4];
    assert_eq!(v, vec![1, 2, 3, 4]);
}
```

#### 关键语法：`$(...)*`

- `$($x:expr),*`：
    
    - `$x:expr`：匹配一个表达式；
    - `$(...)*`：重复零次或多次；
    - `,`：分隔符（可以是逗号、分号等）。
    
- `$(temp_vec.push($x);)*`：
    
    - 对每个匹配到的 `$x`，生成一行 `temp_vec.push($x);`。

## 三、声明宏的核心特性：**卫生性（Hygiene）**

Rust 的声明宏是**卫生宏（Hygienic Macros）**，这是它和 C 语言宏最大的区别 ——**不会产生变量名冲突**。

### 例子：卫生宏 vs 不卫生宏

我们写一个宏，定义一个变量 `x`，然后看看卫生性的作用：
```rust
macro_rules! create_x {
    () => {
        let x = 42;
    };
}

fn main() {
    let x = 10; // 外部定义的 x
    create_x!(); // 宏内部定义的 x
    println!("{}", x); // 输出：10（外部的 x 没被宏内部的 x 覆盖！）
}
```

在 C 语言中，宏内部的 `x` 会覆盖外部的 `x`，但 Rust 的卫生宏会自动处理变量名，避免冲突 —— 这是 Rust 宏安全的重要保障。

---

## 四、声明宏 vs 过程宏：怎么选

|维度|声明宏（`macro_rules!`）|过程宏（Proc Macros）|
|---|---|---|
|**核心思想**|模式匹配|编译期运行的程序|
|**复杂度**|简单，适合模式化的代码生成|复杂，适合需要深度分析代码的场景|
|**卫生性**|天然卫生|需要手动保证卫生|
|**例子**|`vec!`、`println!`、`format!`|`#[derive(Serialize)]`、自定义 Derive 宏|
|**适用场景**|简单的代码重复、模式化生成|需要解析结构体 / 枚举、生成复杂 Trait 实现|

## 五、实战：写一个实用的声明宏 `max!`

我们写一个 `max!` 宏，计算多个值的最大值：
```rust
macro_rules! max {
    // 基础情况：1 个值，返回它自己
    ($x:expr) => { $x };
    // 递归情况：比较第一个值和剩下的最大值
    ($x:expr, $($y:expr),+) => {
        std::cmp::max($x, max!($($y),+))
    };
}

fn main() {
    assert_eq!(max!(5), 5);
    assert_eq!(max!(3, 7), 7);
    assert_eq!(max!(2, 9, 4, 1), 9);
}
```

这个宏用了**递归**，是声明宏中常用的技巧 —— 通过递归处理重复的模式。

---

## 六、总结：声明宏的核心要点

1. **定义方式**：`macro_rules! 宏名 { 模式 => 代码 }`；
2. **核心思想**：模式匹配，像 `match` 一样匹配代码结构；
3. **强大功能**：重复模式 `$(...)*`，处理可变参数；
4. **关键特性**：卫生性，避免变量名冲突；
5. **适用场景**：简单的代码重复、模式化生成（比如 `vec!`、`println!`）。
