# 初始线程的能力槽
```c
// 初始线程的根 CNode 是一个能力数组
cap_t root_cnode[seL4_NumInitialCaps] = {
    [0]  = Null Capability,           // seL4_CapNull
    [1]  = InitThread TCB Cap,        // seL4_CapInitThreadTCB  
    [2]  = InitThread CNode Cap,      // seL4_CapInitThreadCNode
    [3]  = InitThread VSpace Cap,     // seL4_CapInitThreadVSpace
    [4]  = IRQ Control Cap,           // seL4_CapIRQControl
    [5]  = ASID Control Cap,          // seL4_CapASIDControl
    [6]  = InitThread ASID Pool Cap,  // seL4_CapInitThreadASIDPool
    [7]  = IO Port Control Cap,       // seL4_CapIOPortControl
    [8]  = IO Space Cap,              // seL4_CapIOSpace
    [9]  = BootInfo Frame Cap,        // seL4_CapBootInfoFrame
    [10] = InitThread IPC Buffer Cap, // seL4_CapInitThreadIPCBuffer
    [11] = Domain Control Cap,        // seL4_CapDomain
    [12] = SMMU SID Control Cap,      // seL4_CapSMMUSIDControl
    [13] = SMMU CB Control Cap,       // seL4_CapSMMUCBControl
    [14] = InitThread SC Cap,         // seL4_CapInitThreadSC
    [15] = SMC Cap,                   // seL4_CapSMC
};
```

# 普通用户线程的能力
普通用户线程的能力槽与初始线程有**根本的不同**——***它们没有固定的预定义能力槽***，而是通过**能力派生和动态分配**来构建的
## 用户线程能力空间结构

### 1. **用户线程的根 CNode**
```c
// 用户线程的根 CNode 通常是空的或最小化的
cap_t user_root_cnode[USER_CNODE_SLOTS] = {
    [0] = Null Cap,                    // 必须的Null能力
    // 其他槽位初始为Null，等待动态填充
};
```

### 2. **典型用户线程能力布局**
```text
用户线程根 CNode:
[0]  Null Capability (必需)
[1]  线程自身的 TCB Capability
[2]  线程的 IPC Buffer Capability  
[3]  线程的 VSpace Capability (如果有地址空间)
[4]  线程的 SC Capability (调度上下文)
[5..N] 其他动态授予的能力
    - Endpoint 能力
    - Notification 能力  
    - 内存帧能力
    - 其他对象能力
```

## 能力创建和授予过程

### 1. **线程创建时授予基本能力**
```c
// 创建新线程时授予基本能力集
seL4_Error create_user_thread(seL4_CPtr tcb_cap, seL4_CPtr root_cnode_cap) {
    // 在目标CNode中安装基本能力
    seL4_CNode_Mint(root_cnode_cap, USER_TCB_SLOT,     seL4_AllRights, 
                    root_cnode_cap, tcb_cap,           seL4_AllRights);
    seL4_CNode_Mint(root_cnode_cap, USER_IPCBUF_SLOT,  seL4_AllRights,
                    root_cnode_cap, ipcbuf_cap,        seL4_AllRights);
    seL4_CNode_Mint(root_cnode_cap, USER_VSPACE_SLOT,  seL4_AllRights,
                    root_cnode_cap, vspace_cap,        seL4_AllRights);
}
```

### 2. **动态能力授予示例**
```c
// 服务器向客户端线程授予Endpoint能力
seL4_Error grant_endpoint_to_client(seL4_CPtr client_cnode, 
                                    seL4_CPtr endpoint_cap) {
    // 在客户端CNode的空槽位安装Endpoint能力
    return seL4_CNode_Copy(client_cnode, CLIENT_EP_SLOT, seL4_WordBits,
                          root_cnode, endpoint_cap, seL4_AllRights);
}
```

## 用户线程能力管理

### 1. **能力引用 (CPtr) 解析**

用户线程通过 **能力引用** 访问能力，这些引用是**相对于线程自身CNode的索引**：
```c
// 用户线程视角的能力引用
typedef seL4_Word seL4_CPtr;

// 在用户代码中的使用
void user_thread_entry(void) {
    // 这些索引是相对于线程自身CNode的
    seL4_CPtr my_tcb_cap = 1;      // 假设TCB在槽位1
    seL4_CPtr my_ep_cap = 4;       // 假设Endpoint在槽位4
    
    seL4_Send(my_ep_cap, message);
}
```

### 2. **能力空间配置**
```c
// 用户线程的CSpace（能力空间）配置
typedef struct user_cspace_config {
    seL4_CPtr root_cnode_cap;      // 根CNode能力
    seL4_Word cnode_size_bits;     // CNode大小(2^bits个槽位)
    seL4_CPtr tcb_slot;            // TCB能力槽位
    seL4_CPtr ipcbuf_slot;         // IPC缓冲区能力槽位
    seL4_CPtr vspace_slot;         // 地址空间能力槽位
} user_cspace_config_t;
```

## 与初始线程的关键区别

### 初始线程 vs 用户线程：

| 特性         | 初始线程         | 用户线程       |
| ---------- | ------------ | ---------- |
| **能力槽布局**  | 固定预定义        | 动态分配       |
| **系统管理能力** | 有完整系统管理能力    | 只有授予的特定能力  |
| **自引用能力**  | 有根CNode自引用能力 | 通常没有自引用能力  |
| **能力索引**   | 全局固定值        | 相对于自身CNode |
| **权限范围**   | 完整系统权限       | 最小权限原则     |

## 实际用户线程示例

### 1. **简单用户线程能力集**
```c
// 一个最小用户线程的能力布局
enum user_caps {
    USER_CAP_NULL = 0,
    USER_CAP_TCB = 1,           // 自身TCB
    USER_CAP_IPCBUF = 2,        // IPC缓冲区
    USER_CAP_ENDPOINT = 3,      // 通信端点
    USER_CAP_NOTIFICATION = 4,  // 通知对象
    USER_NUM_CAPS = 5
};

cap_t user_cnode[USER_NUM_CAPS] = {
    [USER_CAP_NULL] = null_cap,
    [USER_CAP_TCB] = my_tcb_cap,           // 只读权限
    [USER_CAP_IPCBUF] = ipcbuf_cap,        // 读写权限
    [USER_CAP_ENDPOINT] = endpoint_cap,    // 发送权限
    [USER_CAP_NOTIFICATION] = notification_cap, // 信号权限
};
```

### 2. **能力授予代码**

```c
// 创建并配置用户线程能力空间
seL4_Error setup_user_cspace(seL4_CPtr user_root_cnode, 
                             seL4_CPtr user_tcb_cap) {
    // 1. 安装TCB能力（限制权限）
    seL4_CNode_Mint(user_root_cnode, USER_CAP_TCB, seL4_CanRead,
                    root_cnode, user_tcb_cap, seL4_AllRights);
    
    // 2. 安装IPC缓冲区能力
    seL4_CNode_Mint(user_root_cnode, USER_CAP_IPCBUF, seL4_AllRights,
                    root_cnode, ipcbuf_cap, seL4_AllRights);
    
    // 3. 安装Endpoint能力（只授予发送权限）
    seL4_CNode_Mint(user_root_cnode, USER_CAP_ENDPOINT, seL4_CanSend,
                    root_cnode, endpoint_cap, seL4_AllRights);
}

```
## 安全含义

### 1. **最小权限原则**
```c
// 用户线程只能访问明确授予的能力
// 没有默认的系统管理能力
```

### 2. **能力隔离**
```c
// 每个用户线程有独立的能力空间
// 线程A无法访问线程B的能力，除非显式授予
```

### 3. **无特权升级**
```c
// 用户线程无法获取超过初始授予的权限
// 所有能力操作都经过严格的权限检查
```

## 总结

普通用户线程的能力槽：

- **没有固定布局**：槽位位置由创建者动态决定
    
- **最小能力集**：通常只有自身TCB、IPC缓冲区等基本能力
    
- **动态授予**：其他能力通过显式的授予操作添加
    
- **相对索引**：能力引用是相对于线程自身CNode的
    
- **严格权限控制**：遵循最小权限原则，没有默认的系统权限
    

这种设计确保了系统的安全性和隔离性，每个线程只能访问被明确授权的资源。
