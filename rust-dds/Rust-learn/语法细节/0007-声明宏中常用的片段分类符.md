```rust
// 宏的定义 macro_rules! greet { 
	// 模式匹配 ($name:expr) => { 
		// 宏的展开 println!("Hello, {}!", $name); }; }
```

# `expr` 的作用：**匹配并捕获一个 Rust 表达式**

在 `macro_rules!` 中，`expr` 是一个**片段分类符（Fragment Specifier）**，它的作用是：

1. **告诉编译器**：这里要匹配的是一个**合法的 Rust 表达式**（Expression）；
2. **捕获内容**：将匹配到的表达式绑定到前面的变量（如 `$name`）；
3. **保证展开安全**：在宏展开时，会把捕获的内容**当作表达式**处理，确保语法正确。

# 结合你的例子看
```rust
macro_rules! greet {
    // 👇 这里的 expr 表示：$name 必须匹配一个 Rust 表达式
    ($name:expr) => {
        println!("Hello, {}!", $name);
    };
}
```

## 你可以这样用（匹配各种表达式）
```rust
fn main() {
    // 1. 匹配字符串字面量（是表达式）
    greet!("Alice");

    // 2. 匹配变量（是表达式）
    let name = String::from("Bob");
    greet!(name);

    // 3. 匹配复杂表达式（如函数调用、运算）
    greet!(format!("Charlie {}", 123));
    greet!({
        let mut s = String::from("Dave");
        s.push_str("!");
        s
    });
}
```

# 为什么要用 `expr`？（核心价值）

## 1. 语法检查：确保匹配到的是合法表达式

如果你传的不是表达式，编译器会**在宏展开前就报错**，而不是等到展开后出现莫名其妙的语法错误。

### 反例：如果传的不是表达式
```rust
// ❌ 编译报错：expected expression, found `let`
greet!(let x = 10;);
```

## 2. 展开时正确处理：当作表达式使用

在宏展开时，`$name` 会被**原封不动地替换成你匹配到的表达式**，并且编译器会确保它在新的位置也是一个合法的表达式。

# 常见片段分类符对比（帮你理解 `expr` 的定位）
Rust 提供了多种片段分类符，用于匹配不同的语法元素：

|分类符|匹配的内容|例子|
|---|---|---|
|`expr`|**表达式**（最常用）|`1 + 2`、`x`、`"hello"`|
|`stmt`|语句|`let x = 10;`|
|`ty`|类型|`i32`、`String`、`Vec<T>`|
|`pat`|模式|`Some(x)`、`(a, b)`|
|`ident`|标识符（变量名 / 函数名）|`x`、`my_function`|
|`path`|路径|`std::vec::Vec`|
|`tt`|TokenTree（单个语法树节点）|任意单个 Token 或带括号的组|

# 对比：`expr` vs `ident`

## 用 `expr`（你的例子）
```rust
macro_rules! greet_expr {
    ($name:expr) => { println!("Hello, {}!", $name); };
}

fn main() {
    greet_expr!("Alice"); // ✅ 可以匹配字符串字面量
    let name = "Bob";
    greet_expr!(name);    // ✅ 可以匹配变量
}
```

## 如果换成 `ident`
```rust
macro_rules! greet_ident {
    ($name:ident) => { println!("Hello, {}!", $name); };
}

fn main() {
    // greet_ident!("Alice"); // ❌ 编译报错：expected identifier, found string literal
    let name = "Bob";
    greet_ident!(name);    // ✅ 只能匹配标识符（变量名）
}
```

---
# 总结
1. **`expr` 是片段分类符**：专门用来匹配 Rust 表达式；
2. **核心作用**：语法检查 + 捕获表达式 + 安全展开；
3. **适用场景**：当你的宏需要接收任意表达式作为输入时（如函数参数、运算结果等）。
