## 核心教学原则（必须严格遵守，复刻原博客风格）

1. **先破后立，先纠误区**：开篇先点出 Rust 模块系统对新手的核心困惑，先纠正最常见的错误认知，再讲正确用法，避免用户带着错误预设学习。
2. **拒绝跨语言对比**：明确告知用户「Rust 的模块系统设计非常独特，请以开放的心态阅读，不要强行和其他语言的模块机制做对比」，避免用户陷入思维定式。
3. **显式优先，无隐式映射**：核心强调「Rust 的模块树必须显式构建，文件系统树和编译器看到的模块树没有隐式的 1:1 映射」，这是贯穿全程的核心准则。
4. **渐进式实例教学**：采用从简单到复杂的 3 层递进示例，完全贴合真实项目的文件结构，每一步只新增一个知识点，避免信息过载。
5. **直观的代码对比**：所有代码修改都用「改前 / 改后」的 +/- 格式展示，让用户一眼看到需要修改的内容，降低理解门槛。
6. **关键字一句话定义**：每个核心关键字（mod/pub/use/super/crate）都必须给出一句精准、好记的定义，再配合示例讲解。
7. **模块树可视化辅助**：每完成一个示例，必须说明「此时编译器看到的模块树是什么样的」，打通用户的「文件系统认知」和「编译器模块树认知」的壁垒。
8. **实用优先，拒绝空泛理论**：所有知识点都围绕真实项目的使用场景，不讲解脱离实际的语法细节，确保用户学完就能直接用到项目中。

## 核心知识体系（必须 100% 覆盖，无遗漏）

### 1. 模块树核心规则

- Rust 的二进制 crate 根是 `src/main.rs`，库 crate 根是 `src/lib.rs`，这是编译器唯一默认识别的模块根
- 必须使用 `mod` 关键字显式声明子模块，才能将文件 / 文件夹加入模块树
- `mod xxx;` 声明时，编译器会自动查找同目录下的 `xxx.rs` 或 `xxx/mod.rs` 文件
- 子模块必须在**父模块文件中声明**，不能在自身文件中声明自己为模块
- 模块树的层级结构，完全由 `mod` 关键字的声明位置决定，而非文件系统的文件夹结构

### 2. 核心关键字精准定义与使用规则

表格

|关键字|一句话核心定义|使用规则|
|---|---|---|
|`mod`|声明一个子模块，将对应文件 / 文件夹加入模块树|1. 必须在父模块中声明；2. 语法：`mod 模块名;`；3. 编译器自动匹配 `模块名.rs` 或 `模块名/mod.rs`|
|`pub`|将项（函数、结构体、模块等）标记为公开，允许其他模块访问|1. Rust 中所有项默认私有；2. 子模块可以访问父模块的私有项，父模块不能访问子模块的私有项；3. 要让其他模块访问，必须加`pub`；4. 文件夹模块需要在`mod.rs`中用`pub mod 子模块名;`公开子模块|
|`use`|缩短模块路径，将长路径绑定到短别名，简化代码|1. 语法：`use 完整路径::项名;`；2. 可以用`as`设置别名：`use 路径::项名 as 别名;`；3. 不会创建新的模块，仅做路径简化|
|`crate`|模块路径的根，代表当前 crate 的模块树根|1. 绝对路径的起点，例如`crate::a::b::func();`；2. 任何模块中都可以使用，不受当前模块层级影响|
|`super`|模块路径的父级，代表当前模块的父作用域|1. 相对路径的父级起点，例如`super::a::func();`；2. 用于同层级模块之间的互相调用，避免写冗长的绝对路径|

### 3. 路径规则

- 绝对路径：以`crate`开头，从模块树根开始的完整路径，全项目通用
- 相对路径：以当前模块、`super`开头，仅在当前模块作用域内有效
- 访问子模块的项，必须满足：模块本身是公开的（`pub mod`）、项本身是公开的（`pub fn/struct`等）

### 4. 文件夹模块的特殊规则

- 要将一个文件夹作为模块，必须在文件夹内创建`mod.rs`文件，作为该文件夹模块的根
- 文件夹内的子文件，必须在`mod.rs`中用`mod`声明，才能加入模块树
- 要让父模块 / 其他模块访问文件夹内的子模块，必须在`mod.rs`中用`pub mod`公开子模块

### 5. 外部依赖规则

- 在`Cargo.toml`中添加的外部依赖，会自动成为全 crate 全局可用的项，无需用`mod`声明
- 可以直接用`依赖名::项名`访问，也可以用`use`简化路径

### 示例 1：同目录文件的模块导入（main.rs 导入 config.rs）

#### 步骤 1：先展示新手的错误写法，纠正核心误区

- 先给出新手默认会写的代码（无 mod 声明，直接调用）
- 明确指出新手的核心错误：「我们以为文件系统里的 config.rs 是一个模块，编译器就能直接识别，但实际上，编译器此时只看到了根模块 main.rs，因为我们没有显式构建模块树，文件系统和模块树没有隐式映射」
- 可视化对比：「我们看到的文件系统树」vs「编译器看到的模块树」

#### 步骤 2：讲解正确操作，分步修改

1. 第一步：在父模块（main.rs）中用`mod config;`声明子模块，将 config.rs 加入模块树
2. 第二步：用`config::print_config();`调用对应函数
3. 第三步：讲解「默认私有」规则，给 config.rs 中的函数加上`pub`关键字，使其可被访问
4. 给出完整的改前 / 改后代码对比，用 +/- 标记修改内容

#### 步骤 3：展示此时的模块树，确认构建成功

- 明确说明：此时编译器看到的模块树是`crate（根，main.rs）→ config（子模块）`

---

### 示例 2：子目录文件的模块导入（main.rs 导入 routes/health_route.rs）

#### 步骤 1：先讲文件夹模块的规则

- 明确告知：要将 routes 文件夹作为模块，必须创建`routes/mod.rs`，作为文件夹模块的根
- 讲解`mod`关键字的查找规则：`mod routes;`会自动查找`routes.rs`或`routes/mod.rs`

#### 步骤 2：分步修改，完成导入

1. 第一步：创建`routes/mod.rs`文件
2. 第二步：在 main.rs 中用`mod routes;`声明 routes 文件夹模块
3. 第三步：在`routes/mod.rs`中用`pub mod health_route;`声明并公开 health_route 子模块
4. 第四步：给 health_route.rs 中的函数加上`pub`关键字
5. 第五步：在 main.rs 中用`routes::health_route::print_health_route();`调用函数
6. 给出完整的代码修改对比

#### 步骤 3：展示此时的模块树

- 明确说明：此时编译器看到的模块树是`crate → routes → health_route`

---

### 示例 3：跨目录模块调用（main.rs → routes/user_route.rs → models/user_model.rs）

#### 步骤 1：先完成基础的模块声明

1. 创建`models/mod.rs`，声明并公开`user_model`子模块
2. 在 main.rs 中声明`mod models;`
3. 在`routes/mod.rs`中声明并公开`user_route`子模块
4. 给所有需要被调用的函数加上`pub`关键字
5. 先完成 main.rs 对 user_route 的调用

#### 步骤 2：讲解跨模块调用的路径规则

- 明确告知：要在非 main.rs 的文件中调用其他模块，必须从模块树的视角，用绝对路径（crate 开头）或相对路径（super 开头）
- 演示在 user_route.rs 中，用`crate::models::user_model::print_user_model();`调用跨目录的函数
- 补充演示用`super::health_route::print_health_route();`调用同目录的兄弟模块，讲解`super`的用法

#### 步骤 3：讲解`use`关键字的用法，简化路径

- 演示用`use crate::models::user_model::print_user_model;`简化代码，直接调用函数
- 演示用`as`设置别名的用法

#### 步骤 4：展示最终的完整模块树

- 明确说明最终的模块树结构，让用户清晰看到所有模块的层级关系

### 示例 4：外部依赖的使用（可选扩展）

- 讲解外部依赖无需`mod`声明，添加到 Cargo.toml 后即可全局使用
- 演示直接调用和用`use`简化的两种写法

### 收尾：核心知识点总结

用简洁的条目，把所有核心规则再复述一遍，强化记忆，必须和原博客的 Summary 核心对齐：

1. 模块系统是显式的，和文件系统没有 1:1 的隐式映射
2. 我们在父模块中声明子模块，而非在子模块自身文件中声明
3. `mod`关键字用于声明子模块
4. 必须用`pub`关键字将函数、结构体等标记为公开，才能被其他模块使用
5. `use`关键字用于缩短模块路径，简化代码
6. 第三方外部依赖无需显式声明，添加后即可全局使用

## 新手常见误区与纠正方案（必须主动识别并纠正）

表格

|新手常见错误|错误原因|纠正方案|
|---|---|---|
|直接在文件中写`mod xxx;`声明自己，或在同文件中声明同目录的其他文件|误以为 mod 是在自身文件中声明模块，不知道 mod 是在父模块中声明子模块|必须在父模块文件中声明子模块，例如 main.rs 是 config.rs 的父模块，要在 main.rs 中写`mod config;`|
|只声明了`mod xxx;`，但没有给函数 / 结构体加`pub`，编译报错「项是私有的」|不知道 Rust 所有项默认私有，仅声明模块无法访问内部的私有项|给需要被外部访问的函数、结构体、枚举、字段等，都加上`pub`关键字|
|文件夹模块没有创建`mod.rs`，或没有在`mod.rs`中声明子文件|误以为文件夹会被自动识别为模块，不知道必须显式声明|给作为模块的文件夹创建`mod.rs`，并在其中用`mod`声明子文件，需要公开则加`pub`|
|跨模块调用时路径写错，找不到模块|没有从模块树的视角写路径，误以为是文件系统的相对路径|优先使用以`crate`开头的绝对路径，确保全项目通用；同层级兄弟模块可以用`super`开头的相对路径|
|导入外部依赖时用`mod`声明|误以为外部依赖需要用 mod 加入模块树|外部依赖添加到 Cargo.toml 后自动全局可用，无需用 mod 声明，直接使用即可|
